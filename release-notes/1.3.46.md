# Release 1.3.46

## Summary
Fixes misleading Android billing catalog telemetry on 1.3.45: probe failures (`BILLING_UNAVAILABLE`, `PRODUCT_DETAILS` unsupported, network retries) no longer report as `billing_product_catalog_status: empty`. Paywall waits for billing readiness before catalog fetch.

## Product
- **Android:** `BillingCatalogStatusResolver` emits `billing_not_ready`, `product_details_unsupported`, or `catalog_probe_pending` instead of false `empty` when Play is not query-ready.
- **Android:** Paywall catalog fetch waits on `ensureBillingReadyForPurchase()` and re-checks PRODUCT_DETAILS support before querying SKUs.
- **Ops:** PostHog billing HogQL alert excludes `probe_blocked_reason` so empty-catalog alerts reflect real SKU gaps only.

## Release operations
- Requires active Play products: `elite_tactical` (annual + monthly base plans), `pro_base` (one-time).
- **Do not claim billing fixed until PostHog shows `billing_product_catalog_status: ok` on build 1.3.46+** (not merely absence of `empty` events).
